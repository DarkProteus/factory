## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Веха M1. Пакет save умеет сериализовать партию в строку (TASK-11), но игра его не использует: при обновлении страницы партия пропадает. Нужно подключить save в app: загрузка при старте и автосохранение.

Решения (основная сессия, 2026-11-20):
- Код хранения — в app (packages/app/src/persist.ts), save остаётся чистым. Хранилище передаётся параметром (интерфейс getItem/setItem/removeItem), чтобы тестировать без браузера фейковым объектом.
- Ключ localStorage: factory.save. Сохранение каждые 30 с игрового времени (1800 тиков, по счётчику тиков в цикле), а также при visibilitychange → hidden и pagehide.
- Старт: есть сохранение — загрузить его; нет — демо-сцена (createDemo). SaveError или исключение localStorage (приватный режим, квота) не роняют игру: стартует демо, в интерфейсе показывается сообщение по docs/style.md («Сообщение об ошибке сохранения»); битое сохранение перекладывается под ключ factory.save.broken, чтобы его не затёрло.
- Кнопка «Новая партия» по docs/style.md (раздел «Раскладка M1»): после подтверждения удаляет factory.save и начинает демо-сцену заново (без перезагрузки страницы, если это просто; иначе location.reload()).
- Известное ограничение (не чинить в этой задаче): render запоминает исходный запас залежи при первом показе, поэтому после загрузки залежи рисуются по 5 камней до следующего снижения. Для точности нужен исходный запас в состоянии sim — отдельная задача.
<!-- SECTION:DESCRIPTION:END -->
