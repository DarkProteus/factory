## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Веха M0–M1. Пакет `render` на PixiJS рисует состояние `sim` и только читает его. Рендер интерполирует между тиками симуляции. Графика геометрическая: иконки и простые формы в одной палитре, без художника. Приёмка проверяется глазами за минуту.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 На экране видна тайловая карта с залежами
- [x] #2 Здания рисуются в своих клетках с учётом размера и направления
- [x] #3 Предметы на конвейере видны и движутся плавно между тиками

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Архитектурные решения (основная сессия, 2026-11-20):
- API: createRenderer(host) -> { beforeTick(state), draw(state, alpha), camera, destroy }. Состояние принимается как DeepReadonly<SimState>; render держит только свои кеши (снимок конвейеров, исходный запас залежей, момент укладки у манипулятора).
- Цикл в app: фиксированный шаг 60 тиков/с с аккумулятором (не больше 5 тиков за кадр). Перед каждым tick() вызывается beforeTick, затем draw(state, alpha), где alpha = остаток аккумулятора / шаг.
- Интерполяция предметов: снимок конвейеров (id -> [{item,pos}]) до тика. Предмет текущего тика сопоставляется с предметом снимка того же конвейера и вида, у которого pos в [pos - beltSpeed, pos]; при зазоре BELT_GAP > beltSpeed такой один. Не нашёлся — пришёл с соседнего конвейера: prev = pos - beltSpeed (рисуется на стыке клеток); pos = 0 — положен манипулятором/буром, без интерполяции. Циклы зданий (бур, манипулятор, печь) интерполируются как progress + alpha.
- Камера — чистая логика (camera.ts, тестируется без WebGL); управление мышью/клавиатурой — controls.ts в render: перетаскивание средней или правой кнопкой, WASD/стрелки, колесо — зум к курсору ×1.15, 0.5..3.
- Сцена: земля одним Graphics (рисуется один раз), залежи — отдельный Graphics, перерисовка при смене числа камней; у каждого здания свой Graphics (повёрнут на dir×90°, рисуется в ориентации N), предметы на конвейерах — один Graphics на кадр.
- Пока нет интерфейса стройки (TASK-10), app показывает демо-сцену (app/src/demo.ts), собранную командами build.

Проверка: camera.test (панорама, зум к курсору, границы 0.5..3), interp.test (плавное движение, затор, стык клеток), scene.test (600 тиков завода, кадры рисуются из глубоко замороженной копии, хеш состояния не меняется). Глазами: скриншоты Playwright, демо-сцена.
