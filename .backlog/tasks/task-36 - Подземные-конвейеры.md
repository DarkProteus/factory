## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Решение по архитектуре (основная сессия, 2026-11-21):
- Роль хранится в здании: поле underground: 'in' | 'out', задаётся при постановке. Новый подземный становится выходом, если позади (до undergroundReach + 1 клеток) ближайший подземный того же типа и направления — вход без пары; иначе входом. Помощник sim undergroundPlacement(state, type, x, y, dir) -> { role, partner } нужен и призраку.
- Пара выводится, не хранится (кеш по topologyVersion вместе с сегментами): вход и выход в паре, если каждый — ближайший подземный того же типа и направления у другого в пределах дальности. Подземный того же типа и направления внутри пролёта пары ставить нельзя (canPlace), иначе пары ломаются. Другой тип или направление в пролёте — можно.
- Тоннель — продолжение ленты входа: длина ленты входа = BELT_CELL × (1 + клеток между) при паре и BELT_CELL без пары. moveBelt получает длину ленты параметром. Предмет с pos > BELT_CELL — в тоннеле. Выход — обычная клетка ленты, отдаёт вперёд как конвейер.
- Вход принимает ленту только сзади (боковое вливание запрещено), выход не принимает ленту ни с какой стороны. Манипулятор кладёт и во вход, и в выход; берёт из входа только предметы с pos <= BELT_CELL.
- Снос входа возвращает всю его ленту (вместе с тоннелем). Снос выхода возвращает свою ленту и предметы тоннеля из ленты входа (pos > BELT_CELL); проверка «помещается» — по всем вместе.
- Призрак: при роли «выход» подсвечивает вход-пару; при роли «вход» — подпись «вход» (вместо «нет пары»: роль определяется постановкой, выход без пары невозможен).
