# Завод с обороной — дизайн-док

Nov 16, 2026 · @Andrii

## Концепт

Браузерная 2D-игра про автоматизацию: игрок строит завод на враждебной планете, а рост завода притягивает волны врагов. Ориентиры по жанру: Factorio и Mindustry.

Цель партии: дойти по дереву исследований до финальной постройки (рабочее название «Маяк») и удержать базу, пока она запускается.

Три опоры дизайна:

- **Автоматизируется всё.** Любое ручное действие позже заменяется постройкой.
- **Оборона — часть логистики.** Турели не стреляют сами по себе: патроны к ним едут по конвейеру, как любой другой предмет.
- **Угроза растёт от твоего же роста.** Чем больше завод шумит и загрязняет, тем сильнее волны. Игрок сам выбирает темп.

Платформа: браузер на десктопе, мышь и клавиатура, хостинг на GitHub Pages. Графика геометрическая: иконки и простые формы, без художника.

Открытый вопрос: название игры.

## Игровой цикл

Игра состоит из трёх вложенных циклов, а ритм задаёт таймер волн.

1. **Минута.** Поставить здание, провести конвейер, найти и починить затык в цепочке.
2. **Десять минут.** Открыть технологию, перестроить под неё производство, усилить оборону до следующей волны.
3. **Партия, 3–6 часов.** Пройти путь от ручной добычи до запуска Маяка.

Между волнами идёт спокойная стройка. Волна проверяет, хватает ли турелям патронов и энергии. Партия проиграна, когда уничтожено ядро базы.

## Системы

Тринадцать систем, каждая привязана к вехе, в которой появляется.

| Система | Что делает | Веха |
| --- | --- | --- |
| Карта и сетка | Тайловая карта, залежи ресурсов, размещение зданий по клеткам | M1 |
| Добыча | Бур стоит на залежи и выдаёт руду | M1 |
| Конвейеры | Переносят предметы; позже разделители и подземные участки | M1, M2 |
| Манипуляторы | Перекладывают предметы между конвейером и зданием | M1 |
| Производство | Печи и сборщики работают по рецептам | M1, M2 |
| Сохранения | Запись и загрузка партии | M1 |
| Инвентарь | Предметы игрока; при сносе содержимое здания, а с M2 и само здание, уходит в инвентарь | M1, M2 |
| Энергия | Генераторы и сеть столбов; при нехватке здания замедляются | M2 |
| Исследования | Лаборатории потребляют научные пакеты и открывают технологии | M3 |
| Враги | Гнёзда на карте, волны по таймеру, движение к ядру базы | M4 |
| Оборона | Стены и турели; патроны приезжают по конвейеру | M4 |
| Загрязнение | Здания копят «шум», он усиливает следующие волны | M5 |
| Финал | Постройка и запуск Маяка, экран победы и поражения | M5 |

Упрощение относительно Factorio для первой версии: у конвейера один ряд предметов, без двух полос.

**Инвентарь и стоимость зданий.** У игрока есть инвентарь. Правила, как в Factorio:

- Инвентарь состоит из ячеек, в ячейке лежат предметы одного вида, не больше `stack` этого предмета. Число ячеек задаётся в `content`.
- При сносе всё, что лежит в здании (предметы на конвейере, буферы), уходит в инвентарь.
- Сюда входит всё содержимое: предметы на конвейере, выходной буфер, вход крафтера, ячейки контейнера, предмет в руке манипулятора.
- Число ячеек инвентаря — константа `INVENTORY_SLOTS` в `content` (30). В `SimState` инвентарь лежит в поле `inventory` (массив стеков), входит в хеш и сохранение.
- Проверка «помещается» делается сразу для всего содержимого, на копии ячеек.
- Если содержимое не помещается в инвентарь, снос запрещён: команда игнорируется, здание и предметы остаются на месте.
- С M2 постройка стоит предметы из инвентаря, а при сносе само здание возвращается в инвентарь предметом. С этим приходят стартовый набор, ручная добыча и простой крафт.
- В M1 постройка бесплатная, при сносе возвращается только содержимое здания.

## Архитектура

Пять пакетов в одном монорепо, и вся игра живёт в ядре `sim`, которое работает без браузера.

&#91;embedded content: архитектура · 5 пакетов\]

Интерфейс шлёт в ядро команды («поставить бур в клетку 10,4»), ядро раз в тик обновляет состояние, рендер это состояние рисует. Обратных зависимостей нет: `sim` импортирует только `content`.

- **Детерминизм.** В ядре нет `Math.random` и `Date.now`, только генератор с зерном и счётчик тиков. Один и тот же список команд всегда даёт одно и то же состояние.
- **Тик.** Симуляция идёт с фиксированным шагом 60 тиков в секунду, рендер интерполирует между тиками.
- **Стек.** TypeScript, Vite, pnpm workspaces, PixiJS, React, Zustand, Vitest.

## Контент как данные

Весь контент лежит в пакете `content` типизированными таблицами, без логики. Новый предмет, рецепт или враг добавляется записью, а не кодом.

```ts
export const items = {
  ironOre:   { name: 'Железная руда', stack: 50 },
  ironPlate: { name: 'Железная пластина', stack: 100 },
  ammo:      { name: 'Патроны', stack: 100 },
} satisfies Record<string, ItemDef>;

export const recipes = {
  smeltIron: { in: { ironOre: 1 }, out: { ironPlate: 1 }, ticks: 180, madeIn: 'furnace' },
  makeAmmo:  { in: { ironPlate: 2 }, out: { ammo: 1 }, ticks: 120, madeIn: 'assembler' },
} satisfies Record<string, RecipeDef>;

export const buildings = {
  furnace: { size: [2, 2], power: 0,  behavior: 'crafter', hp: 200 },
  turret:  { size: [2, 2], power: 10, behavior: 'turret', ammo: 'ammo', range: 8, hp: 400 },
} satisfies Record<string, BuildingDef>;
```

Поле `behavior` выбирает одно из готовых поведений в ядре: `miner`, `belt`, `inserter`, `crafter`, `container`, `generator`, `lab`, `turret`. `container` — хранилище из ячеек (сундук). Новое поведение пишется кодом один раз, дальше им пользуются любые здания.

Тест-валидатор проверяет, что все ссылки существуют: рецепт не может ссылаться на предмет или здание, которых нет.

## Вехи

Семь вех, каждая заканчивается версией, в которую можно играть по ссылке.

1. **M0. Каркас.** Монорепо, тесты, CI, деплой на GitHub Pages. На экране пустая карта с камерой.
2. **M1. Играбельное ядро.** Бур, конвейер, манипулятор, печь, сундук и сохранение. Руда сама превращается в пластины.
3. **M2. Цепочки.** Сборщики, многоступенчатые рецепты, разделители, энергия. Стоимость зданий, стартовый набор, ручная добыча и простой крафт.
4. **M3. Исследования.** Лаборатории, научные пакеты, дерево технологий, которое открывает здания.
5. **M4. Враги и оборона.** Гнёзда, волны, стены, турели на патронах с конвейера, ядро базы.
6. **M5. Петля угрозы и финал.** Загрязнение усиливает волны, Маяк, победа и поражение.
7. **M6. Полировка.** Обучение, баланс, звук, производительность на больших заводах.

M1 намеренно узкая: это первая точка, где видно, затягивает ли игра. Всё, что не входит в текущую веху, записывается в бэклог и не делается.

## Первые задачи для Backlog.md

Одиннадцать задач закрывают M0 и M1. У каждой есть критерий приёмки, который проверяется тестом или глазами за минуту.

1. **Каркас монорепо.** Пакеты `sim`, `content`, `render`, `app`, `save`. Приёмка: `pnpm test` и `pnpm build` проходят; линтер запрещает импорт `render` и `app` из `sim`.
2. **CI и деплой.** GitHub Actions. Приёмка: тесты идут на каждый PR, ветка main выкладывается на GitHub Pages.
3. **Определения контента.** Типы `ItemDef`, `RecipeDef`, `BuildingDef`, три предмета, один рецепт. Приёмка: тест-валидатор ловит ссылку на несуществующий предмет.
4. **Тик и команды.** Приёмка: одно зерно и один список команд дают одинаковый хеш состояния после 1000 тиков, в двух прогонах подряд.
5. **Сетка и размещение зданий.** Приёмка: здание занимает свои клетки, второе поверх не ставится, снос освобождает клетки.
6. **Бур.** Приёмка: бур на залежи выдаёт одну руду за заданное число тиков; на пустой клетке не выдаёт ничего.
7. **Конвейер.** Приёмка: предмет проходит прямой участок из 10 клеток за расчётное число тиков; при заторе очередь стоит и не теряет предметы; повороты работают.
8. **Манипулятор и печь.** Приёмка: 100 руды превращаются ровно в 100 пластин; печь не забирает больше, чем вмещает.
9. **Рендер и камера.** Приёмка: видны карта, здания и предметы на конвейере; работают панорама и зум.
10. **Интерфейс строительства.** Приёмка: панель зданий, полупрозрачный «призрак» перед установкой, поворот клавишей R, снос.
11. **Сохранение.** Приёмка: после сохранения и загрузки хеш состояния совпадает с исходным.

Задачи 3–8 и 11 целиком проверяются тестами без браузера. Этот список можно отдать агенту как есть и попросить завести задачи в Backlog.

## Инструменты и правила для агента

Четыре инструмента закрывают четыре разные дыры: задачи, архитектуру, навигацию по коду и правки. Все ставятся в M0.

| Инструмент | Зачем | Как ставится | Как используется |
| --- | --- | --- | --- |
| [Backlog.md](https://github.com/MrLesk/Backlog.md) | Задачи лежат md-файлами в репе, с критериями приёмки | `npm i -g backlog.md`, затем `backlog init` в репе | Агент берёт одну задачу, делает, закрывает. Доска: `backlog board` |
| [groma.md](https://github.com/MrLesk/groma.md) | Живая C4-карта архитектуры, задачи Backlog приколоты к компонентам | `npm i -g groma.md`, затем `groma web` | Карта на localhost:4747. Агент уточняет её после каждой вехи |
| [codebase-memory-mcp](https://github.com/DeusData/codebase-memory-mcp) | Граф кода в SQLite: агент спрашивает граф вместо чтения файлов | `npm i -g codebase-memory-mcp`, затем `codebase-memory-mcp install` | В Claude Code сказать «Index this project» |
| [ast-grep](https://ast-grep.github.io) | Поиск и массовые правки по синтаксису, а не по тексту | `pacman -S ast-grep` | `ast-grep --pattern 'шаблон' --lang ts` |

Две оговорки. groma.md пока ранний прототип, первую карту надо проверить глазами. Флаги команд стоит сверить с `--help`, эти инструменты быстро меняются.

Правила, которые идут в `CLAUDE.md`:

- **Одна задача за сессию.** Агент работает только по задаче из Backlog и не трогает код вне её.
- **Готово значит зелёные тесты.** Задача закрывается, когда проходят тесты из её критериев приёмки.
- **Контент только данными.** Новые предметы, рецепты, здания и враги добавляются в `content`. Код ядра меняется, только если не хватает механики.
- **Границы пакетов.** `sim` не импортирует `render`, `app` и DOM. В `sim` нет `Math.random` и `Date.now`.
- **Сначала граф, потом файлы.** Искать код через codebase-memory-mcp и ast-grep, читать файл целиком только перед правкой.
- **Точечные правки.** Менять строки, а не переписывать файлы. Файл держать в пределах 300 строк.
- **Карта после вехи.** В конце каждой вехи обновить карту groma.

По моделям: архитектурные решения и нарезку задач отдавать сильной модели, реализацию по готовым критериям приёмки делать моделью из лимита подписки.

## Риски

Главный риск один: не дойти до версии, в которую можно играть. Остальные технические и решаются заранее.

| Риск | Что с ним делать |
| --- | --- |
| Проект утонет до играбельной версии | M1 узкая; демо на GitHub Pages с первой недели; всё вне текущей вехи только в бэклог |
| Конвейеры тормозят на больших заводах | Хранить конвейер сегментами, а не по одному предмету; тест-бенчмарк с M2 |
| Симуляция перестанет быть детерминированной | Хеш-тест из задачи 4 идёт в CI на каждый PR |
| Сотни врагов ищут путь и просаживают тик | Одно поле путей на всю карту вместо поиска для каждого врага |
| Баланс не сходится | Все числа лежат в `content`; партию можно прогнать скриптом без графики |
| Без художника игра выглядит бедно | Единый геометрический стиль и одна палитра с M0 |
| Инструменты отнимают больше времени, чем экономят | Если инструмент за веху ни разу не помог, убрать его из правил |
